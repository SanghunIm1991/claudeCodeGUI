Local Verification Guide

claudeCodeGUI を実際に触ってみる

Issue登録から工程実行、成果物の確認までを自分の手で一通り動かすための手順書です。あわせて、実装に使った技術要素を用語ごとに解説します。

repo: D:\claudeCodeGUI app: http://localhost:5037 stack: ASP.NET Core + 素のJS
事前準備 起動 操作手順 パス早見表 用語解説 困ったとき

1. 事前準備

3点だけ確認すればすぐ試せます。

  • .NET SDKが入っている（確認済み: 9.0.314。ターミナルで dotnet --version）
  • claude CLIがインストール・ログイン済み（本アプリは C:\Users\21452\.local\bin\claude.exe を呼び出す設定。変更する場合は src/ClaudeCodeGui/appsettings.json の ClaudeCli:Path）
  • 試用に使える空フォルダを1つ用意する（例: C:\temp\try-claudecodegui）。最初から大事なリポジトリを指定しない

2. 起動する

  1. リポジトリのルートでアプリを起動

    cd D:\claudeCodeGUI
dotnet run --project src/ClaudeCodeGui/ClaudeCodeGui.csproj

  2. ブラウザで開く

    Now listening on: http://localhost:5037 の表示を確認したら、ブラウザで http://localhost:5037 を開く（自動起動しない場合は手動で）。

  3. （任意）ヘルスチェック

    http://localhost:5037/api/health にアクセスし {"status":"ok"} が返れば正常起動。

3. 操作してみる

Issueを1件作り、工程を実行して、成果物を確認するまでの一連の流れです。

  1. プロンプトテンプレートを確認する

    上部ナビ「プロンプトテンプレート」を開くと、初回起動時に自動生成された5件（要件定義・設計・実装・テスト・デプロイ）が並んでいます。内容はその場で編集できます。

  2. Issueを新規作成する

    「Issue」タブの「新規Issue」フォームに、タイトル・説明・対象プロジェクトパスを入力して作成します。

    Check

    対象プロジェクトパスは実在するフォルダの絶対パスである必要があります。存在しないパスを指定すると、工程実行は即座に失敗します。

  3. 工程を選んで実行する

    作成したIssueを一覧から選ぶと詳細画面が開きます。「工程実行」欄でテンプレートとパーミッションモードを選び「実行」を押します。

    注意

    bypassPermissions はファイル編集などをすべて自動承認します。試用フォルダ以外では選ばないでください。迷ったら既定の acceptEdits のままで構いません。

  4. ログをリアルタイムに眺める

    claude CLIが対象フォルダをカレントディレクトリにしてバックグラウンドで起動し、その出力が下のログ欄に流れ込みます。ページを閉じずに待ちます。

  5. 実行履歴で結果を確認する

    完了すると「実行履歴」に工程名・状態（succeeded / failed など）・結果の要約が1行追加されます。

  6. 成果物を見て、直接編集する

    画面下部の「成果物」欄で対象プロジェクト配下のファイルを一覧・閲覧できます。ファイルをクリックするとエディタに読み込まれ、「保存」で書き戻せます。

終了するときはターミナルで Ctrl+C。

4. 使った技術要素の解説

辞書的な定義ではなく、このアプリの中で実際にどう使われているかを添えています。

バックエンドの土台

ASP.NET Core / Minimal API ASP.NET Core, Minimal API
C#で書くWebアプリの土台。コントローラークラスを作らず、Program.cs内でapp.MapGet(...)のように直接エンドポイントを書く軽量な流儀を採用。 Issue・テンプレート・工程実行・成果物のAPIはすべてこの形式でProgram.csに定義。
Kestrel built-in web server
ASP.NET Coreに内蔵のWebサーバー本体。dotnet runで起動した際、実際にHTTPリクエストを受けているのはこれ。
wwwroot / 静的ファイル配信 UseStaticFiles
ビルドせずにHTML/CSS/JSをそのまま配信する仕組み。 wwwroot/index.html・app.js・styles.cssがこの仕組みで配信されるフロントエンド一式。

claude CLIの実行エンジン

headlessモード -p / --print
対話画面を出さず、1回のプロンプトを渡して結果を受け取ったら終了するCLIの動作形態。 「工程実行」ボタンを押すと、このモードでclaudeをサブプロセス起動する。
stream-json出力形式 --output-format stream-json
headlessモードの出力形式の一つ。処理の進行に合わせて1行1つのJSONが逐次出力される。 出力を1行ずつ読み取り、ログファイルへの追記とブラウザへの配信を同時に行っている。
permission-mode acceptEdits / bypassPermissions / plan
ファイル編集やコマンド実行のたびに許可を求めるかどうかを決める動作モード。対話画面がないheadless実行では承認する人がいないため、事前に指定する必要がある。 工程実行フォームのプルダウンで選択。既定は編集のみ自動承認するacceptEdits。

ブラウザとの通信

SSE（Server-Sent Events） text/event-stream
サーバーからブラウザへ一方向にテキストを流し込み続けるHTTPの仕組み。チャットのような双方向通信（WebSocket）より単純で、ログ配信のような一方向の用途に向く。 /api/runs/{id}/streamエンドポイントが実行ログをこの形式で流す。
EventSource JavaScript API
ブラウザ標準のJavaScript API。SSEのURLを渡すだけで、届いた行を順番にイベントとして受け取れる。 app.js内でログ欄への逐次描画に使用。

データの持ち方・安全対策

ファイルベースJSON永続化 JsonFileStore
データベースを使わず、1件のレコードを1つのJSONファイルとして保存する方式。個人用のローカルツールという前提でシンプルさを優先した。 Issue・テンプレート・実行履歴が、それぞれruntime-data/issues|templates|runs/配下に1件1ファイルで保存される。
プレースホルダ置換 {{issue.title}} など
プロンプトテンプレート内の文字列を、実際のIssueの値に文字列置換で差し込む仕組み。
パストラバーサル対策 path traversal
../のような相対パスを使って、意図した範囲の外にあるファイルへアクセスされることを防ぐ対策。 成果物ブラウザは、解決後のパスが対象プロジェクトフォルダの外に出ないことを毎回検証している。

5. 困ったときは

ブラウザが自動で開かない／ページが表示されない
ターミナルのログでポート番号を確認し、手動でアクセスしてください。すでに同じポートで別プロセスが起動していると、起動時にエラーが表示されます。その場合は既存のdotnetプロセスを終了してから再実行してください。
工程実行がすぐにfailedになる
まず対象プロジェクトパスが実在するフォルダかどうかを確認してください。存在しない場合は即座に失敗します。実行履歴の結果欄にエラーメッセージが表示されます。
claudeコマンドが見つからないというエラーになる
src/ClaudeCodeGui/appsettings.jsonのClaudeCli:Pathが、実際にインストールされている場所と一致しているか確認してください。
ログが途中で流れなくなった
現状のSSE実装は簡易的で、接続が切れても自動で再購読はしません。ページを再読み込みしてから工程をもう一度実行してください。
